# 00 — Foundation

## Purpose

Project scaffold: React Router v7 framework mode + Vite + Tailwind + TypeScript on Cloudflare Workers with D1, Drizzle ORM, Vitest with the Workers pool, and a CI/CD pipeline. After this feature is merged the public page is reachable but only renders a placeholder; subsequent features wire it up to D1.

## Database

Schema defined in `app/db/schema.ts`, applied via `pnpm db:migrate:local` (or `:prod`).

**`links`**: `id`, `slug` (UNIQUE), `label`, `url`, `position`, `enabled` (default true), `created_at`, `updated_at`.
**`events`**: `id`, `type` ('page_view'|'link_click'), `source`, `raw_path`, `clicked_slug`, `country`, `user_agent`, `referrer`, `created_at`.

No foreign keys. Events store slug as string (append-only history).

## Notes / Decisions

### Rolldown binding pinning

`@react-router/dev`'s typegen and Vite 8's build use `rolldown` (rc.17). Rolldown distributes its native bindings as `optionalDependencies` (one per OS/arch), but **pnpm 9 does not reliably pick them up** — `supportedArchitectures` and `--include=optional` both failed in this environment. As a workaround, the bindings are pinned as direct devDependencies for the two platforms we care about:

- `@rolldown/binding-darwin-arm64@1.0.0-rc.17` — local macOS dev
- `@rolldown/binding-linux-x64-gnu@1.0.0-rc.17` — GitHub Actions runners (ubuntu)

Each binding's package.json has `os`/`cpu` restrictions, so pnpm will skip the wrong-arch one at install time. **Keep these versions in sync with `rolldown` itself** — when rolldown bumps, both bindings need the same bump. If a future pnpm release fixes optional-deps installation, drop both pins and the `pnpm.supportedArchitectures` block in `package.json`.

### D1 ID is wired

`wrangler.jsonc` carries the real `database_id` for the prod `hyan-linkbio` D1. Local dev uses miniflare's sandbox D1 regardless of the configured ID; the value matters only for `wrangler d1 migrations apply --remote` and `wrangler deploy`. The "First-time setup" steps below are kept as a reference for spinning the project up against a fresh Cloudflare account.

### Tailwind v4

Using the new `@tailwindcss/vite` plugin (no PostCSS). `app/app.css` imports `tailwindcss` with `source(".")` so all template files are scanned. Theme overrides go in `@theme {}`.

### React Router 7 framework mode (not SPA)

`react-router.config.ts` has `ssr: true`. The Workers fetch handler in `workers/app.ts` delegates each request to `createRequestHandler`, so loaders and actions run on the edge. **This is not a client-only React Router app.**

### Coverage gate is a ratchet, not a target

The 80%/70% thresholds catch dead code but do not drive design. Per CLAUDE.md, the discipline is TDD on layers where it fits (lib/, loaders, actions, redirect handler, action handlers) — the metric will follow naturally.

## First-time setup (already done — kept as reference for fresh setups)

> All five steps below are complete on this project. They're documented here so a fresh clone (e.g. another artist, a recovery scenario) can repeat them.

1. **Create the production D1 database** (run from your local machine with wrangler authenticated):
   ```bash
   pnpm wrangler login   # if not already
   pnpm wrangler d1 create hyan-linkbio
   ```
   Copy the returned `database_id`.

2. **Update `wrangler.jsonc`** — paste the real ID into the `database_id` field. Commit and push.

3. **Set the GitHub Actions secret** at https://github.com/nathan-hyan/link-in-bio/settings/secrets/actions:
   - `CLOUDFLARE_API_TOKEN` — created from the Cloudflare dashboard using the "Edit Cloudflare Workers" preset PLUS the `D1: Edit` scope. Scope to your account and the `hyan.dev` zone only.

4. **First merge to `main`** triggers the deploy job:
   - `pnpm db:migrate:prod` applies migration `0000_public_loki.sql`
   - `pnpm db:seed:prod` inserts the 5 starting platforms (idempotent)
   - `pnpm run deploy` builds and uploads the Worker (note: `pnpm run`, not `pnpm` — `pnpm deploy` is a built-in command)

5. **Custom domain** — once deployed, attach `link-in-bio.hyan.dev` to the Worker via Cloudflare dashboard → Workers & Pages → hyan-link-in-bio → Settings → Domains & Routes → Add custom domain. Cloudflare auto-provisions the cert.

## Common commands

```bash
pnpm dev                  # local dev server with miniflare D1
pnpm build                # production build (no upload)
pnpm test                 # vitest run
pnpm test:watch           # vitest watch mode
pnpm test:coverage        # vitest with coverage report
pnpm typecheck            # wrangler types + react-router typegen + tsc -b
pnpm db:generate          # generate Drizzle migration from schema diff
pnpm db:migrate:local     # apply migrations to local D1
pnpm db:migrate:prod      # apply migrations to production D1 (used by CI)
pnpm db:seed:local        # seed local D1 with the 5 platforms
pnpm db:seed:prod         # seed production D1 (used by CI, idempotent)
pnpm run deploy           # build + wrangler deploy (used by CI). NOTE: `pnpm deploy` without `run` is a pnpm-builtin command and does NOT run this script.
```
